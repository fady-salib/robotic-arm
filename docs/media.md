# Demonstration evidence guide

No photographs or videos were supplied during this review. Add existing media
without treating unobserved firmware features as demonstrated hardware results.

Recommended organization:

- `docs/media/2024-prototype/`: original hardware images, short captions, dates,
  readable board labels and motor/sensor identifiers.
- `docs/media/current-firmware/`: later bench captures clearly labeled by commit,
  board, AT firmware, wiring, power supply and calibration settings.
- Link large videos from the README using a thumbnail, descriptive title and
  stable URL instead of committing large video binaries. Obtain permission for
  any identifiable people or third-party footage.

Suggested recordings: glove/finger response; muscle input/arm response;
startup/calibration indication; isolated communication-loss behavior. State what
the clip actually shows, whether ECG is connected, the hardware revision, and
whether all motors were powered. Include unsuccessful or limited behavior where
it explains engineering constraints.

Record original two-Uno wiring/communication before replacing anything. A photo
of board labels, original sketches and a short as-built connection table can
resolve the current Uno/Nano discrepancy. Do not label a later simulation or
software test as original physical validation.
